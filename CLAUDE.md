# Renovion Dash

CRM + projectmanagementsysteem voor **Renovion** (renovatiebedrijf, Arnhem — stucwerk, schilderwerk, tegelwerk, badkamerrenovaties, complete renovaties). Gebouwd voor Imad en Raphael.

**Leidende spec: [Renovion_Technische_Briefing_Boyd_v1.pdf](Renovion_Technische_Briefing_Boyd_v1.pdf)** (v1.0, 28 sept 2026, "briefing v2") — lees die bij twijfel over functionele scope. De oudere [technische-briefing.txt](technische-briefing.txt) blijft naslagwerk voor details die v2 niet herhaalt (bijv. automation-templates), maar v2 wint bij conflict. De mockups in de PDF (§18) zijn de stylingreferentie.

## Leidend principe

> Eén omgeving voor het hele proces: aanvraag → calculatie → offerte → contract → projectfasering → uitvoering met foto-bewijs → oplevering → nazorg. Het systeem laat zelf zien wat vandaag aandacht vraagt; Nova automatiseert, de gebruiker houdt regie.

- **Mobile-first, geen uitzonderingen.** Uitvoerders werken volledig vanaf de telefoon.
- **Actie gaat vóór informatie.** De Aandacht-module toont uitsluitend uitzonderingen.
- **Nova stelt voor, de gebruiker beslist** — behalve waar een automation expliciet op "automatisch uitvoeren" staat (briefing §12: per regel instelbaar: alleen signaleren / eerst bevestigen / automatisch).
- **AI-output is altijd een concept** dat een mens bevestigt (calculatieregels, offerteteksten, planningen).

## Domein (briefing v2)

- **Leadpipeline:** Nieuw → Contact → Intake → Offerte → Akkoord → Project (+ Verloren / On hold).
- **Projectfasen 0–8 (§7, `ProjectPhase::NAMES`):** Opdracht & overdracht → Voortraject → Werkvoorbereiding → Inkoop & planning → Uitvoering → Controle & klantacties → Vooroplevering → Oplevering → Nazorg. Elk project krijgt ze automatisch bij aanmaak (`Project::booted`).
- **Fasestatus (`PhaseStatus`):** niet gestart / bezig / wacht op klant / wacht op leverancier / geblokkeerd / gereed. Kleuren: groen = op schema, oranje = aandacht/wachten, rood = geblokkeerd, grijs = niet gestart.
- **Taakstatus:** Te doen → Bezig → Wacht op → Afgerond.
- **Rollen (`UserRole`):** Admin/MT, Sales, Projectleider, Werkvoorbereider, Uitvoerder (voorheen "vakman"; alleen eigen projecten/taken/planning, extreem simpel) en **Klant** (alleen het portaal; `users.customer_id` koppelt aan het klantdossier). Gates: `internal` (iedereen behalve Klant — hele interne omgeving), `manage-crm` (iedereen behalve Uitvoerder en Klant), `manage-team` (alleen Admin; teambeheer toont/maakt geen klant-accounts — die ontstaan via de klantpagina).
- **Klantdossier:** één chronologische timeline per klant. **Audit trail** bij elke belangrijke actie: wie → wat → wanneer → oud → nieuw → bron (Handmatig / Voice / Nova / Automation / Website / WhatsApp).

## Renovion OS (briefing v3, [chat-16-WUfGujJfZekm.pdf](chat-16-WUfGujJfZekm.pdf))

Technische briefing van 31 okt 2026 die het klikbare prototype (rondes 1 t/m 27) vertaalt naar een bouwopdracht: 8 domeinmodules, 11 rollen, ~55 tabellen, 6 bouwfasen. **Vult briefing v2 aan en wint bij conflict over functionele scope.** De adviezen over de stack (Laravel 11+, Inertia/React, PostgreSQL, Reverb, Redis) zijn bewust **niet** overgenomen: de bestaande basis (Blade + Alpine + MySQL) wint, zoals de briefing zelf voorschrijft ("waar de basis al een keuze heeft gemaakt, wint die"). Vormgeving: het klassieke Renovion-design is leidend, het "Fresh"-alternatief is afgewezen.

**Gebouwd uit deze briefing:**
- **Stoplichten (hoofdstuk 7)**: [ProjectHealthService](app/Services/ProjectHealthService.php) rekent per project vier lichten (planning, budget, kwaliteit, klant), vanaf fase 4; het totaal is het slechtste licht. Uitkomst in [ProjectHealth](app/Support/ProjectHealth.php) + [HealthSignal](app/Support/HealthSignal.php) met reden per licht, `expectedProgress` (voortgang tegen plan), grootste blokkade en volgende mijlpaal. `forMany()` scoort een hele lijst zonder query per rij (test bewaakt dat). Regels in [ProjectHealthTest](tests/Feature/ProjectHealthTest.php).
- **Projectcockpit**: bovenaan het projectdossier, vier stoplichtkaarten + voortgang tegen plan (balk met plan-streepje) + volgende mijlpaal + acties en blokkades. Alleen `manage-crm`; uitvoerders houden de simpele voortgangsbalk.
- **Portfolio** op `/portfolio` ([PortfolioController](app/Http/Controllers/PortfolioController.php)): alle lopende projecten met stoplichten, voortgang tegen plan, volgende mijlpaal en grootste blokkade, tellers per licht als filter plus sortering. Stoplicht-badge staat ook op de projectkaarten (dashboard en projectenlijst).
- **Beweging (hoofdstuk 6)**: pagina-opbouw met staggered blokken (620 ms, 55 ms per blok, max 28), waaier voor KPI- en projectkaarten (2,4 graden per positie vanaf het midden), optellende KPI-cijfers met Nederlandse notatie, pop-up-zoom, balkvulling en micro-interacties (knop 96%, kaart 3px omhoog). Alleen `transform`, `opacity` en `filter`. Uit bij `prefers-reduced-motion` en per gebruiker via `users.motion_enabled` (bliksem-icoon in de sidebar, `POST /voorkeuren/beweging`).

## Renovion OS compleet (prototype `renovion-os_29.html`, nov 2026)

Het klikbare prototype dat Raphael zelf maakte (23 bouwrondes, ~40 modules) is helemaal nagebouwd. Alles hieronder staat er, met tests. De informatiearchitectuur komt uit één bron: **[Navigation](app/Support/Navigation.php)** bevat de secties (groepen Werkdag / Werk / Bedrijf), de tabbladen per sectie, de mobiele bottom-nav per rol en de rechtenmatrix. Een menu-item verschijnt pas als zijn route bestaat, dus een module in de bouw laat geen dood item achter. Gate `module` leest die matrix.

**Rollen (11, `UserRole`):** Superadmin, Directie, Sales, Calculator, Projectleider, Werkvoorbereider, Inkoper, Administratie, Uitvoerder, Onderaannemer, Klant. `isExternal()` = Klant en Onderaannemer (eigen portaal, nooit de interne omgeving); `isManagement()` = Superadmin en Directie (inrichting). De rechtenmatrix staat ook als tabel op `/team`, zodat een collega kan opzoeken dat hij iets niet ziet door zijn rol.

**Mijn klussen en werkbonnen** ([JobExecution](app/Models/JobExecution.php), [WorkOrder](app/Models/WorkOrder.php)): een planningsblok wordt een klus. Onderweg melden, veiligheidscheck (LMRA, vijf keer ja), stappen afvinken, melden, afronden. De checklist komt uit [JobChecklistTemplates](app/Support/JobChecklistTemplates.php) (twaalf vakken; `photo_required` markeert de bewijsmomenten). Een stap met verplichte foto gaat niet af zonder foto, en afronden blokkeert zolang zo'n foto mist; open stappen mogen wel en staan dan eerlijk op de bon. Afronden levert direct een werkbon ter controle: uren, ontleed materiaal, bevroren checklist, foto's, naam van wie aftekende. [ApproveWorkOrder](app/Actions/ApproveWorkOrder.php) boekt bij goedkeuren de uren tegen het **op de bon vastgelegde** tarief als kosten en schuift de voortgang op naar rato van de begrote uren (max 25% per bon).

**Begrotingen met hoofdstukken** ([Budget](app/Models/Budget.php), [BudgetTotals](app/Support/BudgetTotals.php)): hoofdstuk (nummer uit de standaard) → paragraaf → regel. Regel = `q · (n · tarief + m + e + o) + v`, met een eigen tarief per regel waar nodig; een tekstregel rekent niet mee. **De staart rekent cumulatief**: winst en risico gaat over de directe kosten plus de algemene kosten. Marge én opslag staan er beide (mensen denken in marge, rekenen in opslag; `surchargeForMargin`/`marginForSurcharge`). Opties staan buiten de aanneemsom tot akkoord, daarna meerwerk met dezelfde staart. Betaalschema waarschuwt als de termijnen niet op 100% uitkomen. Nieuwe begroting start met het skelet uit [BudgetChapterLibrary](app/Support/BudgetChapterLibrary.php). Definitief = regels op slot; lukt niet met regels die een hoeveelheid maar geen prijs hebben.

**Geld**: termijnfactuur haalt zijn bedrag uit de termijn in de begroting (aanneemsom en facturen lopen nooit uit elkaar). [BuildFinalSettlement](app/Actions/BuildFinalSettlement.php) verrekent meerwerk, minderwerk en wat al gefactureerd is, en houdt bij een particulier 5% in (opschortingsrecht, vrij drie maanden na oplevering). Inkoop: een bestelling zonder factuur is een verplichting; een inkoopfactuur telt pas als kosten ná goedkeuring. [CostReviewService](app/Services/CostReviewService.php) zet begroot tegenover werkelijk en verwacht; de gemeten urenfactor weegt mee naar rato van hoeveel uren er al geboekt zijn (volledig vanaf 30% van de begrote uren) en **de verwachting zakt niet onder de begroting zolang het werk loopt** (afwijking van het prototype: daar las een hoge voortgang met weinig geboekte uren als een besparing). [FinanceOverview](app/Services/FinanceOverview.php) voor omzet, werkvoorraad, debiteuren, crediteuren, gewogen pipeline en zes maanden cashflow.

**Verkoop**: [Intake](app/Models/Intake.php) in vijf stappen met vijftien velden en een score over de zeven vragen die een calculator nodig heeft; afronden lukt niet met een open kernvraag. Nova's vervolgvragen volgen uit wat ontbreekt én het soort werk. Opname inplannen zet de afspraak in de planning. Opvolging sorteert op dringendheid (te laat, niets gepland, vandaag, later). [QuoteDashboard](app/Services/QuoteDashboard.php) leest gedrag: vraag gesteld 60%, twee keer gekeken 45%, een keer 35%, nooit geopend 15%; elke opening van de klantlink in `quote_views`; hitrate op aantal én op geld.

**Mensen en partners**: certificaten uit [CertificateCatalogue](app/Support/CertificateCatalogue.php) (signaal 30 dagen vooruit), afwezigheid die uren van de capaciteit afhaalt, [Subcontractor](app/Models/Subcontractor.php) met dossier van negen punten (legitimatie, vier documenten, vier overeenkomsten). Zonder rond dossier geen uitnodiging en geen opdracht; uitnodigen weigert zulke partijen met naam en reden. Prijsaanvragen met het hoofdstuktotaal als budget; een bieding die niet alle posten prijst is niet vergelijkbaar. [AwardRfq](app/Actions/AwardRfq.php) maakt er een verplichting van met opdrachtnummer en een taak voor de getekende bevestiging.

**Kwaliteit en nazorg**: [QualityReview](app/Models/QualityReview.php) met acht opleverstappen, elk met een harde voorwaarde (`blockerFor()` geeft de reden terug, die bij de knop staat). Controlepunten per vak uit [QualityTemplates](app/Support/QualityTemplates.php), plus vier Wkb-stukken bij constructief werk. Restpunten altijd met locatie, toe te wijzen aan eigen mens of partner. De laatste stap zet het project op opgeleverd met de garantietermijn die bij het werk hoort (10 jaar constructief, 2 jaar badkamer/keuken, 1 jaar overig). [ServiceTicket](app/Models/ServiceTicket.php) rekent zelf uit of een melding nog binnen de garantie valt.

**Nova en agents**: acht agents met elk een vak en een menselijke eigenaar ([AgentRegistry](app/Support/AgentRegistry.php)): Nova, Lex, Cato, Prep, Milo, Dex, Finn, Liv. Vijftien skills op vier niveaus (observeren / voorbereiden / protocol uitvoeren / begrensd wijzigen); bij voorbereiden en begrensd beslist een mens. [AgentOrchestrator](app/Services/AgentOrchestrator.php): een goedkeuring legt een **vingerafdruk** van het voorstel vast en vervalt als het voorstel daarna verandert. Wachten is een echte toestand (op goedkeuring, klant, bewijs, leverancier). De audit noteert `agent:milo` of `user:7`, dus of een mens of een agent het deed. Per skill instelbaar: niveau, pauze en bedragsgrens (alleen directie).

**Verder**: rapportages (week, project, sales, financieel, kwaliteit) als momentopname uit live data met een rode stip bij wat aandacht vraagt; marketing met conversie over **wat beslist is** (open aanvragen vertekenen het beeld) en een beste bron die minstens drie aanvragen vraagt; documentenbibliotheek in zes groepen; instellingen voor bedrijfsgegevens en standaardwaarden (geheimen blijven in `.env`, het scherm meldt alleen of ze er zijn); mailteksten met blokken en variabelen waarbij een niet-vulbare variabele als `[ontbreekt: naam]` blijft staan; klantportaal-preview; partnerportaal waar een onderaannemer zijn eigen dossier aanlevert en zelf biedt; planning in week, maand en capaciteit; Academy met twaalf rondleidingen, een leerpad per rol en stappen die wegvallen voor schermen die jouw rol niet heeft.

**De inbox** ([AttentionService](app/Services/AttentionService.php)) filtert op soort, niet op kleur: Te doen (doorsnede van alles wat een handeling vraagt), Actie nodig, Ter bevestiging, Service, Ter info.

**Bewust niet gebouwd:** offline wachtrij in IndexedDB voor de klussen (dat vraagt een service worker en een sync-strategie, en is zinloos zonder veldtest), echte PDF-generatie (nog print-naar-PDF) en mailverzending (geen SMTP). De sectie "Nog te bouwen" uit briefing v2 hierboven blijft gelden voor wat daar nog open staat.

**Demodata:** [RenovionOsDemoSeeder](database/seeders/RenovionOsDemoSeeder.php) vult de nieuwe modules bovenop `DemoSeeder` (begroting met echte regels, lopende klus met foto-bewijs en melding, werkbon ter controle, twee facturen waarvan één te laat, inkoop, twee partners met en zonder rond dossier, prijsaanvraag met bieding, restpunten, servicemelding, agent-uitvoering met openstaand besluit). Alleen local en testing.

## Huisstijl v2 (mockups §18)

## Nova (AI-assistent)

[NovaAssistant](app/Services/NovaAssistant.php) gebruikt `anthropic-ai/sdk` (PHP), model uit `RENOVION_AI_MODEL` (nu `claude-sonnet-5`), key in `.env`. Verplicht patroon (briefing §11):

```
Voice/tekst → intent → gestructureerde JSON-action → validatie → permissions → preview/bevestiging → backend-actie → audit log
```

- Acties v1: `create_task`, `create_appointment`, `create_note`. Nieuwe actie = tool in `tools()` + `validator()` + preview + execute + `ACTIONS`.
- Voice via browser Web Speech API (nl-NL). Endpoints: `POST /nova`, `POST /nova/uitvoeren`, `GET /nova/briefing` (dagbriefing, 3 uur gecachet). UI: chat-sheet in [app.blade.php](resources/views/components/layouts/app.blade.php) + `Alpine.data('nova')` in [app.js](resources/js/app.js). Nova's gezicht: `public/nova.jpg` (`<x-nova-avatar>`).

## Modules

**Offertes en Automations staan beide aan** (code-default `true`); uitzetten kan per module via `.env` (`MODULE_QUOTES=false` / `MODULE_AUTOMATIONS=false`) + caches verversen. Uit = geen routes, geen menu, geen signalen, geen schedule. In tests staan beide aan (phpunit.xml).

## Automations & Aandacht (gebouwd, fundament voor Nova-rules §12)

- **Automations** ([app/Automations](app/Automations)): `BaseAutomation` (modus-afhandeling) + `AutomationRegistry::CLASSES`; idempotent via `AutomationRun::claim()`. Nieuwe regel: class die `BaseAutomation` extendt, acties door `$this->act($signaal, $actie, $novaActie?, $url?)` leiden, registreren in de registry. Draait via `php artisan automations:run`, elke 15 min gescheduled ([routes/console.php](routes/console.php)) — scheduler moet draaien (`schedule:work` lokaal / cron live).
- **Aandacht** ([AttentionService](app/Services/AttentionService.php)): alleen uitzonderingen; badge-teller 5 min gecachet (`attention-count`).
